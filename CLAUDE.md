# Lista — setlist planner for Mass

Offline-first PWA to prepare the music of a Mass: build a list from the songs, change the
key of each one for that list only, read it on a tablet or phone with no connection, print it.
Part of Músicos Católicos. TypeScript client (no framework), Slim 4 + PDO JSON API, own MySQL
database. Layout and commands: `README.md`. Deploy and hosting: `DEPLOY.md`. What is left:
`TODO.md`. Design the owner has settled: `DESIGN-LOCK.md`.

## Locked design

`DESIGN-LOCK.md` lists the parts of the interface the owner has settled: the bar and the sync dot,
the menu, the lists screen with its starred section, the inside of a list, and singing. **Do not
change them** unless the owner asks for it in that session; if a task seems to need it, ask first.
Read that file before touching any screen, and keep its standards (identical on every device, no
font-drawn marks, `rem` spacing) in everything else.

## Source of truth: musicos-catolicos

The public site (`rudypalacios/musicos-catolicos`) owns how a song is read, shown and printed.
This app must behave the same:

- ChordPro parsing (`ChordPro.php`), chord names, Latin/English notation and transposition
  (`Chord.php`, `song.js`), syllable underline (`Syllable.php`) and the print cascade
  (`PrintLayout.php`: normal, compact, two columns, several pages) are **ported to TypeScript
  as they are**. The port is checked against golden fixtures generated by running the PHP
  code, so the two cannot drift silently.
- If something there can be better, **propose it to the owner for approval** before diverging;
  never change the behaviour on your own. When the public site changes, regenerate the fixtures
  (`npm run fixtures -- ../musicos-catolicos`) and read the diff.
- Ported so far: parser, chords and transposition, the lyrics HTML and the syllable splitter
  (`web/src/chordpro/`). Not yet: the print cascade (`PrintLayout.php`), phase 3.
- Chords are stored in English notation, shown in Latin by default. Minor written as `A-` or
  Latin uppercase (`SOL`, `MIm`) is normalised only by the importer, never by the parser.
- Mass parts use the standard names of the Roman Missal (Ofertorio, Señor, ten piedad,
  Cordero de Dios…), not local ones.

## Rules that keep it offline-first

- What the person has offline lives in **IndexedDB** (data) and the worker's **shell cache**
  (the app). The worker never caches `/api/`. Data is never in the shell cache, so a new app
  version cannot wipe it.
- A new version installs in the background and waits; the person accepts it ("Hay una versión
  nueva"). Never `skipWaiting()` on its own.
- Records are created with client-generated UUIDs and synced from a queue, so everything
  works offline. Until synced, the device holds the only copy: say so in the UI.
- The server is the source of truth; a device that loses its storage must be able to recover.
- **Never a blank screen, never a silent wait.** The page carries a splash until the app draws; a
  device that holds songs opens from them without waiting for the network and checks the session in
  the background; every API request has a timeout; an error while starting shows `showFatal`. An
  update says what it is doing at each step (`web/src/updates.ts`, its states are a tested pure
  function). Anything slower than a moment shows a spinner and a sentence.

## Not in production yet (the owner's decision, 2026-10-29)

The app has no real users and no data worth keeping: what is on the owner's server and devices is
test data. **Compatibility with data or clients of earlier versions is not a requirement** until the
owner says production has started. So:

- Do not write shims for old records or old clients: no "a record saved before this field has none"
  fallbacks, no "an older app that sends no value keeps what is stored" rules for a new field, no
  upgrade path that preserves an earlier on-device database (a version may clear it and pull again).
  Shims that already exist (`withStar`, `withShift`, `pickSong`'s `?? 0`, the `COALESCE` for absent
  `starred` / `myShift`) may be removed when the code around them is touched.
- A change of shape is still a **new** migration file (the owner's database has already run the earlier
  ones and the app applies only new files); do not edit an applied one. When resetting the test data
  would make a change simpler, say so and ask the owner (they can only use phpMyAdmin: give the exact steps).
- Say it in `DEPLOY.md` when a change makes the old test data unreadable or wrong.
- **Unchanged:** the offline-first rules, the update flow, validating every input, the tests, and
  `DESIGN-LOCK.md`.
- **It ends** when the owner announces the first production use. From then on the rules below hold in full:
  never edit a deployed migration, keep older apps and stored data working, and write the shims back where a
  change needs them.

## Database

Migrations are numbered `.sql` files in `migrations/`, applied by the app itself on the first
request after a deploy (the host has no shell and the CI only deploys). Never edit one that
has been deployed; add a new file (see "Not in production yet"). Write for MySQL **and** SQLite (tests use SQLite): the
common subset, one `;` per statement, idempotent (`IF NOT EXISTS`). What the subset cannot say
(table charsets) goes in a file named `NNNN_name.mysql.sql` or `.sqlite.sql`, which only that
database applies. Every new MySQL table needs a `.mysql.sql` follow-up that makes it `utf8mb4`:
the host's database may default to 3-byte `utf8`. Run the suite against a
MySQL-compatible server (`TEST_MYSQL_DSN`, see `tests/Support/TestDatabase.php`; MariaDB is what the
sandbox can install, production is MySQL) whenever a migration or a query changes.

## PDF import

`web/src/pdf/layout.ts` (pure, tested) turns the text items of a PDF page into the text the importer
reads, putting every chord over the syllable it is over by its x position; `read.ts` is the pdf.js
glue, loaded lazily. pdf.js must work inside the page's CSP: no eval, no WebAssembly (`useWasm:
false`), its worker is a file of this origin (built first, its URL injected as `__PDF_WORKER_URL__`).
`tests/e2e/pdf.ts` makes a real PDF with Chromium, imports it under the production policy
(`enforcePolicy` in `tests/e2e/lib.ts`, which reads it from `public/.htaccess`) and checks every
chord. The built app splits code (esbuild `splitting`): everything `main` imports statically must be
precached (the build follows the imports), what loads on demand must not be.

## Public repository

Nothing private goes in the repo: no `.env`, no real server paths, user names or database
names in docs (use placeholders), no default credentials. Secrets live in the `production`
environment on GitHub and in `.env` on the server.

## Policies

The app is private (login, `noindex`, no ads, no analytics, nothing loaded from another
domain: the CSP in `public/.htaccess` enforces it). **Before** a change that opens it to other
people, loads anything from another domain, adds analytics or ads, stores new kinds of
personal data or publishes songs of others, tell the owner and propose the privacy text: the
public site's policies (`musicos-catolicos`, `src/Templates/legal/`) must keep describing what
the code really does.

## A fresh sandbox (nothing survives between sessions)

```
composer install && npm install
# MySQL-compatible server for the SQL checks (MariaDB is what apt offers):
apt-get update && apt-get install -y --no-install-recommends mariadb-server
mkdir -p /run/mysqld && chown mysql:mysql /run/mysqld
mysql_install_db --user=mysql --datadir=/var/lib/mysql; (mysqld_safe --user=mysql &) ; sleep 8
mysql -e "CREATE DATABASE lista_test CHARACTER SET utf8mb4; CREATE DATABASE lista_utf8 CHARACTER SET utf8;
  CREATE USER 'lista'@'127.0.0.1' IDENTIFIED BY 'lista';
  GRANT ALL ON lista_test.* TO 'lista'@'127.0.0.1'; GRANT ALL ON lista_utf8.* TO 'lista'@'127.0.0.1';"
# then: TEST_MYSQL_DSN='mysql:host=127.0.0.1;dbname=lista_utf8;charset=utf8mb4' vendor/bin/phpunit
```

Chromium and Playwright are preinstalled (the e2e scripts load Playwright with `createRequire`). The
fixtures need the public site next to this repo (`add_repo` `rudypalacios/musicos-catolicos`, clone it as
`../musicos-catolicos`). Do not `pkill -f` a pattern that appears in your own command line, and do not
chain a force-push into a longer command: both end the shell.
